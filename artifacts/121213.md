## AC review

The AC field is present.
Scenarios: 12
AC-01: Successful login. Given a registered account, when the user enters that email and the correct password and clicks Login, the user is authenticated and redirected to the SNAP dashboard/home page.
AC-02: Email required. When the registered email field is empty, the Login button stays disabled, whether or not a password has been entered.
AC-03: Password required. When the password field is empty, the Login button stays disabled, whether or not a valid email has been entered.
AC-04: Email format validation. When the user enters an incorrectly formatted email, such as user@domain, and provides a password, an inline validation error says the email format is invalid, and the user stays on the login page.
AC-05: Invalid credentials. When the user submits an unregistered email, or a registered email with the wrong password, an error says the credentials are invalid, and the user stays on the login page.
AC-06: Password cleared after failed login. After a failed login caused by invalid credentials, the password field is cleared and the user must enter the password again.
AC-07: Password visibility — Show. When the user has entered a password and clicks Show, the password is displayed as plain text.
AC-08: Password visibility — Hide. When the password is shown as plain text and the user clicks Hide, the password is masked again.
AC-09: Forgot Password navigation. When the user clicks Forgot Password?, the user is redirected to the password recovery page.
AC-10: Login button state. The Login button stays disabled while either the email or the password is empty, and it becomes available only when both fields contain input.
AC-11: Login page retention. After a validation or authentication failure, the user stays on the login page and the entered email remains in the email field.
AC-12: Secure password handling. The password field masks characters by default and shows the password as plain text only after the user clicks Show.
